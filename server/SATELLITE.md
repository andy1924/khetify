Satellite monitoring setup · India

- Backend: set CDSE_CLIENT_ID and CDSE_CLIENT_SECRET from a registered Copernicus Data Space OAuth client. Never prefix secrets with EXPO_PUBLIC. Existing server startup: node server/index.mjs.
- App: set EXPO_PUBLIC_FIELD_API_URL to the reachable HTTPS backend URL; configure PRICE_ALLOWED_ORIGIN for web. Credentials are never sent to the app.
- Provider: Sentinel-2 L2A Catalog + Statistical APIs. Last 30 days, latest three distinct capture days; SCL cloud/unusable mask, NDVI, polygon pixel coverage. Statistics use complete UTC days so short acquisition windows are not skipped; adjacent tiles from the same day are combined. Coverage divides observed pixels by geometryPixelCount, excluding pixels outside the field. Separate output masks exclude cloudy/invalid pixels from NDVI while retaining them in the quality calculation. Signals only; no chemical soil estimates. No fixture observations or alerts.
- The app automatically requests observations when a saved field opens. The latest capture requests a 768 × 768 true-color PNG with bilinear resampling, surrounding context (at least 600 m across), and an overlaid field boundary. This is a smoother presentation, not higher-resolution source imagery: the source remains approximately 10 m. Statistics still use the original exact polygon, never the larger preview bounds.
- Successful responses are cached in server memory for 15 minutes, with a maximum of 24 field entries and in-flight deduplication. No precise boundary or preview is written to disk; restart clears the cache. Capture timestamps never change on cache hits. Refresh images explicitly bypasses the response cache; image failures are not cached.
- Negative/nonfinite reflectance and zero denominators are excluded from NDVI. Backend and client both reject values outside [-1, 1] instead of clamping them. An urban boundary is not automatically a crop field; mixed soil, vegetation, buildings and water affect NDVI. No land-use classification or pest diagnosis is inferred.
- Official access/coverage docs (checked 2026-10-24): https://documentation.dataspace.copernicus.eu/APIs/SentinelHub/Overview/Authentication.html and https://documentation.dataspace.copernicus.eu/APIs/SentinelHub/Data/S2L2A.html . Registered account, OAuth client, available quota and field-specific acquisitions required. Actual coverage is queried rather than assumed.
- India: Nominatim searches use countrycodes=in. Coordinate requests are bounded to 6–38 N, 68–98 E (a service envelope, not cadastral/country verification). Sentinel-2 includes India; actual field acquisitions are checked at request time. KVK/extension review is required for pest concerns.
- Maps: existing /api/places Nominatim lookup and OpenStreetMap tiles with attribution. No plot-number lookup. Public OSM services require policy-compliant usage; production volume needs suitable hosting/service agreement.
- Fields and private pending reports use the existing session reducer; restart/reset clears them. Authenticated persistence, expert review UI and push delivery are not connected. Plant photo assessment has its own opt-in flow; see PLANT_HEALTH.md. Do not deploy anonymous precise-field storage endpoints.
- server/pest-alerts.mjs is an internal delivery boundary requiring a trusted review worker, authoritative current consent/withdrawal state, recipient fields and an idempotent send adapter. No public confirmation endpoint. Wire authentication, durable reports and notification delivery before enabling broadcast; recheck consent/status before dispatch. Payloads omit coordinates.
- TypeScript/lint and focused provider validation/alert consent tests are available. Live imagery requires credentials. On 2026-10-24, a sample polygon near 20 N, 75 E returned live NDVI of approximately 0.687 (2026-10-22) and 0.561 (2026-10-20), with 100% field coverage. A cloudy capture withheld NDVI. This verifies the provider for that sample, not every field or acquisition.
